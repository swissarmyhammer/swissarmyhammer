title: Give the initial-leader LSP workers the shutdown flag of their tenure

## Problem
`start_lsp_workers_if_leader` (`crates/swissarmyhammer-tools/src/mcp/server/code_context.rs`) reads `shared_db` and `leader_shutdown_flag()` from the workspace at the time the workers start. It does not use the flag of the tenure that started the supervisor. `spawn_drain_supervisor_and_health_loop` reads the tenure flag, then calls `start_workers`. If a step-down and a new promotion both occur between that read and the workspace lock, the LSP indexing workers of the old supervisor get the flag of the new tenure. Those workers then do not stop with the old tenure.

The window is small (the re-election poll is 5 s). The promotion path (`start_indexing_workers_after_promotion`) already uses the tenure flag.

## Fix
- Give `start_lsp_workers_if_leader` the tenure flag from `spawn_lsp_health_loop`, and use it for `LspWorkerSetup::shutdown`.
- Start no worker when that flag is set.

## Tests
- A unit test: a step-down and a promotion, then `start_lsp_workers_if_leader` with the old tenure flag starts no worker. #lsp-fix #bug
