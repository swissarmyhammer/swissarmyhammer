    ## Research findings (2026-10-17)

    ### Cause: CONFIRMED
    - Rust std issue rust-lang/rust#95584 (open): "std::process::Command::spawn() leaks file descriptors on unix platforms that don't have pipe2()". On macOS, std makes a pipe with `pipe()` and then sets `FD_CLOEXEC` in a second call. A process that a different thread spawns between the two calls gets both pipe ends. https://github.com/rust-lang/rust/issues/95584
    - Thus a sibling test process can hold the stdout/stderr capture pipe of a different test. That test then shows LEAK, although it starts no child process.
    - Nextest fixed this in its own code: PR nextest-rs/nextest#3553 "stop concurrent spawns inheriting capture pipes", merged 2026-09-15. https://github.com/nextest-rs/nextest/pull/3553 . The fix adds a process-wide RwLock: pipe creation takes the write lock, spawn takes the read lock. Nextest now makes the capture pipes itself (not `Stdio::piped()`). The PR measured no speed loss.
    - First release with the fix: 0.9.145 (2026-09-16). Changelog: "Capture pipes no longer leak into concurrently spawned sibling tests on platforms like Apple's, which could cause false leak reports (#3553)." https://nexte.st/changelog
    - Related: nextest-rs/nextest#1469 (open, same symptom on Windows/FreeBSD/Linux). https://github.com/nextest-rs/nextest/issues/1469
    - 0.9.148 (2026-10-07, latest) also has: "The leak timeout is no longer restarted each time a leaked handle produces output" (#3646).

## Problem
`cargo nextest run -p swissarmyhammer-lsp` on macOS (nextest 0.9.116, aarch64-apple-darwin) shows LEAK markers on random tests in a parallel run. Tests that start no child process also get the marker, for example `daemon::tests::jsonrpc::test_jsonrpc_multiple_messages` and `daemon::tests::jsonrpc::test_read_jsonrpc_eof_after_first_header`. Thus the test code does not cause these markers.

## Evidence (2026-10-17)
- Parallel run 1: 237 passed, 1 leaky (`daemon::tests::test_shutdown_resets_session_open_documents`).
- Parallel run 2 (same code): 237 passed, 6 leaky (4 of them are `jsonrpc` tests, which spawn no process).
- `--test-threads=1` run (same code): 237 passed, 0 leaky.

## Probable cause
On macOS there is no `pipe2`. The pipe that nextest makes for one test gets `FD_CLOEXEC` after `pipe()`. A test process that nextest spawns at the same time can get that pipe end. The other test process then holds the stdout or stderr of the first test until it exits, and nextest reports a LEAK. This is not confirmed in the nextest source.

## Work
- Confirm the cause (nextest issue tracker, nextest and Rust std source).
- Decide the correct fix with a person: for example a nextest upgrade, a `leak-timeout` setting in `.config/nextest.toml`, or a test group. Do not change the nextest configuration without a decision.
