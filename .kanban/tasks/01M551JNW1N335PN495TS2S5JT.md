## Problem
`cargo nextest run -p swissarmyhammer-lsp` on macOS (nextest 0.9.116, aarch64-apple-darwin) shows LEAK markers on random tests in a parallel run. Tests that start no child process also get the marker, for example `daemon::tests::jsonrpc::test_jsonrpc_multiple_messages` and `daemon::tests::jsonrpc::test_read_jsonrpc_eof_after_first_header`. Thus the test code does not cause these markers.

## Evidence (2026-10-17)
- Parallel run 1: 237 passed, 1 leaky (`daemon::tests::test_shutdown_resets_session_open_documents`).
- Parallel run 2 (same code): 237 passed, 6 leaky (4 of them are `jsonrpc` tests, which spawn no process).
- `--test-threads=1` run (same code): 237 passed, 0 leaky.

## Probable cause
On macOS there is no `pipe2`. The pipe that nextest makes for one test gets `FD_CLOEXEC` after `pipe()`. A test process that nextest spawns at the same time can get that pipe end. The other test process then holds the stdout or stderr of the first test until it exits, and nextest reports a LEAK. This is not confirmed in the nextest source.

## Work
- Confirm the cause (nextest issue tracker, nextest and Rust std source).
- Decide the correct fix with a person: for example a nextest upgrade, a `leak-timeout` setting in `.config/nextest.toml`, or a test group. Do not change the nextest configuration without a decision.
