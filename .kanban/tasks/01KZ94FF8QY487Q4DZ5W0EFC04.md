    DISCOVERY / DESIGN DIVERGENCE — the card says "A TreeSitterProbe", but that is not possible together with the card's own second bullet ("reuse the existing duplicate/similar detection"):

    - `TreeSitterProbe::run(&self, &TreeSitterProbeContext)` receives ONLY a path, the after parse, and the before parse. It has no index connection and no embedding corpus, by design ("plain logic over one changed file and its parse").
    - The only duplicate/similar detection in the repo is embedding-backed: `swissarmyhammer_code_context::find_duplicates_in(corpus, file, &options)` over `load_all_embedded_chunks(conn)`. There is no structural/tree-sitter clone detector anywhere in `swissarmyhammer-sem` or `swissarmyhammer-code-context`.
    - A clone-cluster probe also never reads the parse: cluster membership comes from indexed chunks, and "did the diff touch this member" comes from `FileChange`, not from the tree.

    So the probe lands in the FIRST probe family — one new `ProbeOp` variant beside `Callers`/`Duplicates`/`Similar`/`Complexity` in `review/probes.rs`, sharing the corpus `run_probes` already loads once. Everything the card asks for is unchanged by this: one catalog entry, declared by name in a validator's `probes:` list, rows on the existing `ProbeResult` path, no second similarity engine.

    What the existing `duplicates` probe gives, and why it is not enough:
    - per changed file: `find_duplicates_in` rows for EVERY match, touched or untouched, with no diff overlay.
    - `<changed-set>`: pairwise comparison of changed blocks against each other — by construction only members the change TOUCHED. It can never name an untouched sibling.

    Plan:
    - name `clone-siblings`, kind `Candidate` (the corpus is the index, so an empty list is not the fact "no clones exist" — the rule judges).
    - overlay: for each file under review, pull its clusters from `find_duplicates_in`; drop every member whose file is also under review; keep one row per remaining sibling site, holding the closest changed member it mirrors.
    - one aggregate `ProbeResult` on the `<changed-set>` target so it rides the existing `select_shared_probe_results` / `shared_probe_results` path (a target that is neither a file path nor a changed symbol is silently dropped by `probe_result_for_file`). `"<changed-set>"` is currently an unnamed literal in both `probes.rs` and `scope.rs` — naming it is a prerequisite of adding a third writer.
    - wire-up: add to `completeness` `probes:`, and teach `rules/invariant-propagation.md` (the sibling-sites rule) to consume the rows.

It reads the clusters `find_duplicates_in` returns over the corpus `run_probes` already loads once, and only SUBTRACTS: a cluster member whose file is under review is a site the change reached; every survivor is a sibling it did not. Result rides `CHANGED_SET_TARGET` as batch-scoped shared evidence, because a cluster — and the dedup — span files.

A TreeSitterProbe that finds sibling sites the diff did NOT touch.

- Reuse the existing duplicate/similar detection to get clone clusters that include changed code.
- Overlay the diff on each cluster: report which cluster members the diff touched and which it left untouched.
- One ProbeRow per untouched sibling: its location, the touched member it mirrors, and the similarity evidence.

Wire-up:
- Add the probe to the `completeness` set's `probes:` list.
- Update the sibling-sites completeness rule to consume the rows: the siblings are found for you; judge whether each untouched one needed the change.

Acceptance:
- A fixture with 3 near-copies where the diff edits 2 yields one row naming the third.
- A change with no cluster membership yields no rows.
