## What

The chat side no longer chooses an executor, so remove the machinery that
chose one. Claude becomes hardcoded. The haiku-versus-default choice stays,
but as a plain configuration field, not a model-name lookup.

- Delete the llama-executor model YAMLs from `builtin/models/`: `qwen.yaml`,
  `qwen-0.6b-test.yaml`, `qwen-0.8b-mtp-test.yaml`, `GLM.yaml`,
  `MiniMax-2.5.yaml`.
- KEEP the embedding model YAMLs `nomic-embed-code.yaml` and
  `qwen-embedding.yaml`. The embedding stack still resolves them through
  `ModelManager`, so the loader must keep working for those.
- Remove the executor field and the executor enum from the chat model
  configuration in `crates/swissarmyhammer-config/src/model.rs`. Claude is the
  only chat executor.
- Replace the review model-name resolution: `resolve_review_agent_name`
  currently maps the review scope to `claude-code-haiku` by name. Turn that
  into a boolean-or-enum configuration field that picks the Claude CLI model
  switch directly, so `claude-code.yaml` and `claude-code-haiku.yaml` are no
  longer needed to express the choice.
- Remove `extract_model_flag` and the `--model` global flag from
  `apps/swissarmyhammer-cli/src/main.rs` (line 290) and the
  `model_override` parameter it feeds into `initialize_tool_context`
  (line 310), unless the new configuration field needs a flag — in which case
  rename it to match.

Find the remaining sites with
`grep -rn "resolve_review_agent_name\|claude-code-haiku\|executor" crates/swissarmyhammer-config/ crates/swissarmyhammer-agent/ apps/swissarmyhammer-cli/`.
