title: Use one ignore filter in the code-context and diagnostics watchers

## Problem
Two file watchers watch the full workspace tree. They filter only by file extension. They do not obey `.gitignore`.
- `crates/swissarmyhammer-tools/src/mcp/tools/code_context/watcher.rs` — `process_ok_events` uses only `is_source_file`.
- `crates/swissarmyhammer-diagnostics/src/watcher.rs` — uses only `is_diagnosable`. For each `.swift` event it sends `didOpen` and a diagnostics pull to the LSP.

The startup walk and the reconcile walk (`crates/swissarmyhammer-code-context/src/cleanup.rs` `walk_and_hash`, `WalkBuilder` with `git_ignore(true)`) obey `.gitignore`. The watchers do not.

## Result in the field
In the FoundationModelsKanban workspace, `.code-context/index.db` has 102,219 files. 101,972 of them are under `.build/`. sourcekit-lsp opened files in `.build/checkouts/<pkg>/`. Then it made a new workspace for each checkout and started a background index in `<pkg>/.build/index-build`. That index writes thousands of files. The watchers see them and send more files to the LSP. This is a feedback loop: sourcekit-lsp ran at 560% CPU and fseventsd at about 107% CPU.

## Fix
- Make one shared path filter (for example in `swissarmyhammer-code-context`). It must use the same rules as `walk_and_hash`: `.gitignore`, `.git/info/exclude`, and hidden files.
- Add hard rules that always skip these directories, also when no `.gitignore` exists: `.build/`, `target/`, `node_modules/`, `.git/`, `.code-context/`, `.sah/`.
- Use the filter in `walk_and_hash`, in the code-context watcher, and in the diagnostics watcher.
- Load the gitignore matcher one time when the watcher starts. Do not build it for each event.

## Acceptance criteria
- An event for `<root>/.build/checkouts/X/Sources/a.swift` does not add a row to `indexed_files`.
- An event for a path that `.gitignore` lists does not add a row.
- The diagnostics watcher does not send `didOpen` for an ignored path.
- An event for `<root>/Sources/a.swift` still adds a dirty row.

## Tests
- Unit tests for the shared filter (gitignored path, hard-rule path in a workspace with no `.gitignore`, normal source path).
- A test for `process_ok_events` (or the function that it calls) with a `.build/` path and a normal path.
- A test for the diagnostics watcher event filter. #lsp-fix #bug
