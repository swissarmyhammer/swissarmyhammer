## Problem
Two tests in `crates/swissarmyhammer-entity/src/watcher.rs` fail on this machine:
- `watcher::tests::test_attachment_create_emits_event`
- `watcher::tests::test_attachment_remove_emits_event`

Both panic with "expected AttachmentChanged within 10s". They use the FSEvents backend. fseventsd runs at about 110% CPU on this machine (the same cause as ^ygk17ma). The create test failed again when it ran alone. The remove test passed alone after 5.6 s.

These failures came in the `^1j31ywv` test run. That change does not touch the entity crate, and the entity crate does not depend on `swissarmyhammer-lsp`.

## Fix
- Make sure that the cause is the fseventsd load: run the tests after fseventsd is restarted.
- If the cause is the load, make the tests tolerate a slow FSEvents delivery (a longer wait, as in the tree-sitter watcher tests), or use a polling backend in the tests.

## Acceptance criteria
- The two tests pass 10 times in a row with `cargo nextest run -p swissarmyhammer-entity`. #test-failure
