title: Load the ignore rules again when a .gitignore or .ignore file changes
---
## Problem
The code-context watcher and the diagnostics watcher load `IgnoreFilter` one time, when they start (`IgnoreFilter::load`). When a `.gitignore`, `.ignore` or `.git/info/exclude` file changes, the watchers use the old rules until sah starts again. The reconcile walk every 5 minutes reads the current rules, so the index becomes correct after some time. But during that time the watchers can add rows that the new rules ignore. Also, the LSP can get `didOpen` for those paths.

## Fix
- In both watchers, when an event batch has a path whose file name is `.gitignore` or `.ignore`, or the path is `.git/info/exclude`, build a new `IgnoreFilter` with `IgnoreFilter::load` and use it for that batch and for the batches after it.
- Do not read the ignore files again for each event.
- Note: `.git/` is a hard-skip directory. Check `.git/info/exclude` before the filter drops the event.

## Acceptance criteria
- After a `.gitignore` change adds `gen/`, the next event for `gen/a.rs` adds no row, and sah does not start again.
- An event batch with no ignore-file change does not load the rules again.

## Tests
- A unit test for the batch function of each watcher: first a batch that changes `.gitignore`, then a batch for a path that the new rule ignores. #lsp-fix
