`split_frontmatter` in `crates/swissarmyhammer-skills/src/skill_loader.rs` is a private copy of the frontmatter split. `parse_skill_md` calls it for every real `SKILL.md`.

It does `starts_with("---")`, then `find("\n---")`, then takes the remainder from `end_pos + 4`.

## Why it is wrong

The closer is anchored on the left only. `\n---` matches a line that starts with three hyphens and continues with anything else, so `\n----` and `\n---x` both close the frontmatter. The canonical `split_frontmatter_body` closes only on a line whose content is exactly three hyphens.

The fixed `end_pos + 4` also assumes the delimiter line is `\n---\n`. On a CRLF file the body keeps a leading `\r` or loses a byte.

## What reads it

Every `SKILL.md` that `parse_skill_md` loads. Twenty-one builtin `SKILL.md` and `VALIDATOR.md` files already write `description: >-` as a folded block scalar with indented multi-line prose, which is where a three-hyphen run appears in practice.

## Also in the crate, test scope only

`frontmatter_map` in the `#[cfg(test)]` module of `crates/swissarmyhammer-skills/src/deploy.rs` carries the same `find("\n---")` shape. It round-trips `format_skill_md` output. Converge it too, so the crate holds one rule.

## Required change

Call `swissarmyhammer_common::frontmatter::split_frontmatter_body`. Do not write another copy. `swissarmyhammer-skills/Cargo.toml` already depends on `swissarmyhammer-common`, and there is no cycle.

## Acceptance

- No frontmatter split of the skills crate's own remains.
- RED first: a `SKILL.md` whose `description` block scalar holds a three-hyphen run keeps every frontmatter key.
- A closing line of `----` or `---x` does not close the frontmatter.
- A CRLF `SKILL.md` gives a byte-exact body.
- No behavior change for well-formed input. Existing tests pass unedited.
